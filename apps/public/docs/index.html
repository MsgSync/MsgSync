Quickstart

Create an API key in Developer Portal → API Keys, then send your first message with the HTTPS API.

# Your API base URL
curl https://api.msgsync.dev/v2/messages \
  -H "Authorization: Bearer $MSGSYNC_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "recipient": "+12025550194",
    "content": "Your verification code is 482913",
    "metadata": { "profile": "OTP" }
  }'
Accepted immediately. A successful response returns a message ID. Use that ID to query delivery status or receive a DLR webhook.

Authentication

Send your API key as a Bearer token on every request. Keys should only be used from trusted server-side environments.

ParameterTypeRequiredDescription
AuthorizationheaderYesBearer token in the form Bearer <api_key>.
Idempotency-KeyheaderRecommendedUnique key used to safely retry a request.
X-Request-IDheaderOptionalCustom request identifier for support and tracing.

Campaigns

Create a campaign with POST /v2/campaigns, then start or schedule it from the Campaign Management console or API.

POST /v2/campaigns

Create

Provide a name, template, contact list, sender ID, and optional schedule.

POST /v2/campaigns/:id/start

Launch

Start a draft campaign immediately. Scheduled campaigns begin at their configured time.

GET /v2/campaigns/:id

Track

Inspect status, recipient count, delivery totals, and completedAt timestamps.

POST /v2/campaigns/:id/pause

Control

Pause and resume delivery while preserving campaign configuration and audit history.

HLR / MNP lookup

Use GET /v2/lookups/info?phone=+12025550194 to retrieve validity, MCC/MNC, carrier, porting, and roaming status.

FieldTypeDescription
phonestringRequired E.164 number to resolve.
validbooleanWhether the number is valid and reachable.
mcc / mncstringMobile country and network codes.
portedbooleanWhether the number has changed its serving network.

Rates & routing

List effective rates with GET /v2/network/rates/:planId. Rates are selected by destination, network, prefix, and profile. Routing uses LCR, priority, or weighted modes.

Never negative. Accounts cannot spend below zero. When balance reaches zero, new delivery is suspended automatically until credit is added.

Billing & balance

Query invoices and transactions with GET /v2/invoices and GET /v2/organizations/:id/transactions. Billing policies support ON_ATTEMPT, ON_SUBMISSION, and ON_DELIVERY.

Security

Protect integrations with TLS 1.3, app-based 2FA for privileged users, country-based login restrictions, content screening, sender allowlists, and URL blocking.

Content screening responses

CodeMeaning
CONTENT_REJECTED_KEYWORDMessage contains a blocked keyword.
CONTENT_REJECTED_URLMessage contains a blocked URL domain.
SENDER_NOT_ALLOWEDSender ID is not in the organization allowlist.
BALANCE_EXHAUSTEDAccount is suspended because its balance is zero.
